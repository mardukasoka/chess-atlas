Migrate the existing Shatranj profile onto the shared generic rule kernel while preserving current Chess Atlas behavior exactly.

Do not remove the legacy path yet.

GOAL

Use Shatranj as the first historical ruleset migration to prove that the shared movement kernel supports non-modern chess movement correctly.

Keep the existing Shatranj implementation as the reference implementation for parity testing.

MOVEMENT MAPPING

Map Shatranj pieces through the shared kernel:

- rook → ordinary sliding rook movement
- king → ordinary one-step king movement
- knight → ordinary knight jump
- pawn → one-step forward only, with existing capture behavior
- ferz → one step diagonally
- elephant / alfil → exactly two squares diagonally, jumping over the intermediate square

The elephant jump is especially important:

It is a jump, not a sliding bishop move.

It must ignore occupancy on the intermediate square but obey occupancy rules at the destination.

PRESERVE EXISTING BEHAVIOR

Do not change:

- board setup
- promotion behavior
- stalemate handling
- bare-king rules
- check/checkmate logic
- turn management
- move execution
- any Shatranj-specific victory conditions already implemented

These remain ChessEngine responsibilities unless an existing rule is already safely represented by the shared kernel.

PARITY TESTS

Compare legacy and shared-rule Shatranj paths for:

- full starting position

- elephant blocked by friendly destination
- elephant capturing enemy destination
- pawn one-step

- king-safety filtering
- representative short move sequence

Assert equivalent pseudo-legal and legal destination sets.

Do not change observable behavior to satisfy the new kernel.

If parity differs, stop and report the discrepancy.

shatranj-rules.js

using the existing:

- geometry.js
- rules.js

Keep variant-specific movement definitions outside the generic rule kernel unless they are genuinely reusable primitives.

Do not hard-code Shatranj concepts into "rules.js".
